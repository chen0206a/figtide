## 14-1-3 可移植性修改（逐条列出改动位置）

1. **`updated_at`**：找出所有更新 `experiments`、`charts` 的 UPDATE 语句（`grep -rn "UPDATE experiments\|UPDATE charts" backend/src/main/java`），逐条加上 `updated_at=CURRENT_TIMESTAMP(3)`。补测试：更新后 `updated_at` 严格变大，且列表排序随之变化；MySQL、H2 各跑一次。
2. **`recover()` 的延迟计算**：去掉 `TIMESTAMPDIFF`，在 Java 里用该行的 `created_at` 和当前时间算出 `latency_ms`，作为参数传入。行为（字段含义、单位：毫秒）不变。补测试覆盖这一路径（模拟一个其他实例中断的运行）。
3. **`FOR SHARE`**：按 14-1-2 的实测结果处理。H2 不支持，就统一改成 `FOR UPDATE`，并在汇报里说明锁变强、语义不变。
4. **`REPEATABLE_READ`**：按实测结果处理。H2 支持就不动；不支持，停下汇报，不要自行更改隔离级别。
5. **时区**：H2 的 `TIMESTAMP` 不带时区，会按 JVM 默认时区换算。H2 相关测试统一用 UTC 运行（surefire `-Duser.timezone=UTC`），并补一条测试：写入一个 `Instant`，读出来完全相同。在 `DESKTOP-PLAN.md` 第 3 节补一句：启动器必须以 `-Duser.timezone=UTC` 启动 JVM（14-2 执行）。
