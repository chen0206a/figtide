## 1. 方法与现场

- **空库起步**：为确认"第一次使用"的观感，重建了隔离库 `labflow_e2e`（`DROP` + `CREATE`），后端 8089 连该库，前端 5179，未开启 `labflow.test-support`。真实工作区 `labflow` 库与 8086 主栈全程未动。
- **脚本化模型**：助手环节用仓库自带的 `frontend/e2e/fixtures/compatible-provider.cjs`（`labflow-fixture`，127.0.0.1:18769）代替真模型，因此面板里出现的模型名与地址是夹具值，不是真实服务商信息。
- **按首次使用路径走一遍**：介绍页 → 开始创作 → 空首页 → 新建项目 → 导入 CSV → 新建图表 → 编辑 → 助手（未配置 / 已配置）→ 导出 → 实验页 → 数据页 → 管理项目 → 快捷操作 → 四类报错。
- 每屏记录 `document.title`、URL、可见文案，截图存 `docs/product-audit/`。共 21 张。
- 判断口径：**用户看到的文字**。代码层面的"有没有这个功能"不在本次范围内。

最值得先改的五条：

1. **上传非法文件没有任何拦截**（F1）。一段中文散文被当成"1 行 1 列"的表格，字段名就是那句话，页面还给出"常量列 / 建议：分组"的建议，`确认导入` 可用。用户第一次误传文件就会得到一份垃圾数据集。
2. **`Failed to fetch` 直接出现在 toast 里**（A11 / F2）。这是浏览器原始异常；同一时刻整页错误页却写的是"无法连接 Java 服务"——两处口径也不一致。
3. **助手面板把测试夹具名、端口、token 计数一并展示**（A1 / A2）。`labflow-fixture`、`127.0.0.1:18769`、`本次会话 · 已用 20,340 / 上限 180,000` 对研究用户没有意义。
4. **"原始数据只读"在一条流程里说了五遍**（B1）。数据页副标题、表格脚注、导入说明、编辑器、首页页脚各一次，越强调越像免责声明。
5. **三处开发视角的说明句**（C2 / C3 / C4）。例如"本轮附带最近 1 轮对话。刷新后可恢复仍存活的会话。"——这是实现细节，不是用户语言。
