## 已复现的问题

### R1：草稿写入失败，仍可能承诺已保存在本机（优先）

位置：`frontend/src/lib/draftWriter.ts:35-43`、`frontend/src/editor/workbench/useChartSave.tsx:101-106`。

`DraftWriter.has()` 在存在 pending 时直接返回 true。pending 只是进程内待写数据；`flush()` 遇到存储配额或权限异常时保留 pending，尚未写入 localStorage。保存接口离线后，useChartSave 依赖 has() 显示“修改仍保存在本机草稿中”，用户刷新可能丢失这些修改。

本轮把真实 draftWriter.ts 经 TypeScript transpile 后执行，存储的 setItem 永远抛 quota、getItem 返回 null。实测：

```text
writer.writeNow(key, latest) -> false
storage.getItem(key)        -> null
writer.has(key)             -> true
```

既有 `draftWriter.test.ts` 最后一条测试反而断言 pending 时 has 为 true，`saveFeedback.test.ts` 只测试传入布尔值后的文案，没有覆盖持久化失败与文案的真实连线。

后续修复应核实“当前修改”确实落盘，不能只检查 key 是否存在（可能是旧草稿），也不能把内存 pending 当成已落盘。保留写失败后的重试能力和离开保护。补充：无草稿 + 配额错误、有旧草稿 + 最新写入失败、最新写入成功三种状态，验证最终保存失败提示。
